Тест - набор из одного или нескольких тесткейсов 
Тесткейс - формализованное описание конкретной проверки которая должна быть выполнена для верификации определенного требования или функции ПО
Разновидности тесткейсов 
1. Высокоуровневый тесткейс (тесткейс без конкретных входных данных и ожидаемых результатов как правило схож по структуре с подробно описанным пунктом чеклиста часто встречается в интеграционном тестировании системном тестировании и на уровне дымового тестирования)
2. Низкоуровневый тесткейс (с конкретными входными даннными и ожидаемыми результатами является наиболее классическим видом тесткейсов и представляет собой полностью готовый к выполнению тесткейс)
3. Спецификация тесткейса (документ описывющий набор тесткейсов для тестируемого элемента входят цели входные данные условия и шаги выполнения результаты)
4. Спецификация теста (документ состоящий из спецификации тест дизайна спецификации тесткейса и спецификации тест процедуры)
5. Тест сценарий (документ описывающий последовательность действий по выполнению теста)
Цели написания тесткейсов
- Структурировать и систематизировать подход к тестированию
- Вычислять метрики тестовго покрытия и принимать меры по его увеличнию (в данном случае тесткейссы являются главным источником информации без которого существования подобных метрик теряет смысл)
- Отслеживать соответствие текуей ситуации по плану (сколько примерно понадобится тесткейсов сколько уже есть сколько выполнено из запланированного и тд)
- Уточнить взаимопонимание между разработчиками заказчиками тестировщиками (чаще всего тесткейсы наиболее наглядно показывают поведение приложения чем это отражено в требованиях)
- Хранить информацию для длительного использования и обмена опытом между сотрудниками и командами 
- Проводить регрессионное тестирование и повторное тестирование 
- Повышать качество требований
- Быстро вводить в курс дела нового сотрудника 
Атрибуты тесткейса
1. Идентификатор 
2. Приоритет (показывает выжность может юыть помечен буквами цифрами словами или другим способ кол-во градаций не опрделено часто от 3 до 5 приоритет модет совпадать с важностью требования пользовательснокго сценария или функции с которыми связан тесткейс также может совпадать с потенциальной важностью дефекта на поиск которого направлен тесткейс и со степенью риска связанного с проверяемым тесткейсом требованием сценарием или функцией Основная задача этого атрибута упрощение распределения внимания и услий команды)
3. Связанные с тесткейсом требования (показывает то оснвное требование проверке выполнения которого посвящен тесткейс Можно оставлять поля этого атрибута пустыми либо также можно указывать несколько требований)
4. Модуль и подмодуль приложения (указывают на части прилоения к которым относится тесткейс и позволяют лучше понять его цель)
5. Заглавие тесткейса (упрости и ускорить понимание оснвной идеи тесткейса без обращения к остальным атрибутам Заглавие тесткейса может быть полноценным словосочетанием предложением фразой набором слвосочетаний)
6. Исходные данные необходимые для выполнения тесткейса (позволяют описать все то что должно быть подготовлено до начала выполнения тесткейса Например состояние БД состояние файловой системы и ее объектов состояние серверов и сетефой инфраструктуры)
7. Шаги тесткейса (описывают последовательность действий которые необходимо реализовать в процессе выполнения тесткейса Общие рекомендации по написанию выполнения тест кейса 
	1. Начинать с понятного и очевидного места не писать лишних начальных шагов 
	2. Если в тесткейсе всего один шаг нумеруем его 
	3. Если пишем шаги на русском языке используем глаголы неопределнной формы (открыть ввести добавить)
	4. Можно ссылаться на предыдущие шаги и их диапазоны для сокращения объема текста
	5. Пишите шаги оследовательно без условных конструкций !!!категорически запрещено ссылаться на шаги из дргого тесткейса либо на полностью другой тесткейс целиком!!!)
8.  Ожидаемые результаты (Описывают реакцию приложения на действия опишанные в поле шаги тесткейса)
