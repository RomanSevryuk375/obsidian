Частичные классы, методы и свойства

Суть (The What)

Ключевое слово partial позволяет разделить определение класса, структуры,
интерфейса или записи (record) на несколько физических файлов. Главная
архитектурная задача — изоляция автоматически сгенерированного кода (например,
через [[Source Generators]], EF Core Scaffolding, WPF/WinForms) от ручного кода
разработчика, чтобы при регенерации файлов пользовательская логика не
затиралась.

Как это работает (Under the Hood)

[!info] Уровень среды выполнения Для [[CLR]] (Common Language Runtime) концепции
частичных типов не существует. Разделение существует только на этапе компиляции.
Компилятор [[Roslyn]] собирает все части воедино, создавая в [[IL-код]]
монолитный тип.

  - Слияние метаданных: Атрибуты, интерфейсы, XML-документация и модификаторы
    доступа из всех частей объединяются. Если одна часть объявлена как abstract
    или sealed, весь класс получает это свойство.
  - Primary Constructors (C# 12): Если класс использует первичный конструктор,
    он должен быть объявлен только в одной из partial частей. Остальные части не
    могут его дублировать.
  - Частичные методы: Имеют два режима работы:
    1.  Неявные (старые): Без модификатора доступа. Возвращают void, не имеют
        out параметров. Если реализация не предоставлена, компилятор полностью
        удаляет вызов метода и его метаданные из итогового бинарника (zero-cost
        abstraction).
    2.  Явные (C# 9+): Имеют модификатор доступа (public, private и т.д.) или
        возвращаемый тип отличный от void. Обязаны иметь реализацию.
        Используются для интеграции с генераторами исходного кода.
  - Частичные свойства (C# 13): Позволяют определять свойства в одной части, а
    реализовывать их get/set в другой. Полезно для MVVM-фреймворков и генерации
    INotifyPropertyChanged.

Практический пример

Пример объединяет возможности C# 12 (Primary Constructors) и демонстрацию работы
двух типов частичных методов в контексте обработки заказов.
```csharp
// Файл 1: OrderProcessor.cs (Написан разработчиком)
public partial class OrderProcessor(string processorName) // Primary Constructor только в одной части
{
    public string ProcessorName { get; } = processorName;

    // Опциональный метод (нет модификатора). 
    // Если не реализовать в другой части, вызов исчезнет из IL-кода.
    partial void OnOrderProcessed(Guid orderId);

    // Обязательный метод (есть модификатор доступа C# 9+).
    // Генератор кода или другой файл обязан предоставить реализацию.
    private partial bool ValidateOrder(Guid orderId);

    public void Process(Guid orderId)
    {
        if (!ValidateOrder(orderId)) 
            return;
        
        // Бизнес-логика...
        
        // Если OnOrderProcessed не реализован, этот вызов удаляется при компиляции
        OnOrderProcessed(orderId); 
    }
}

// Файл 2: OrderProcessor.Generated.cs (Сгенерирован автоматически / Source Generator)
public partial class OrderProcessor
{
    // Реализация обязательного частичного метода
    private partial bool ValidateOrder(Guid orderId)
    {
        // Сгенерированная логика валидации
        return orderId != Guid.Empty;
    }

    // Реализация опционального частичного метода
    partial void OnOrderProcessed(Guid orderId)
    {
        Console.WriteLine($"Order {orderId} processed by {ProcessorName}.");
    }
}
```
Ошибки и Best Practices

[!danger] Anti-pattern: Сокрытие технического долга (God Object) Использование
partial для дробления огромного класса на несколько файлов (например,
User.Data.cs, User.Validation.cs, User.Business.cs). Это маскирует нарушение
[[Single Responsibility Principle]]. Решение: Использовать композицию и
внедрение зависимостей вместо разбиения монолита на частичные классы.

[!warning] Ограничения Вы не можете использовать partial для делегатов или
перечислений (enum). Все части должны находиться в одном пространстве имен
(namespace) и сборке (assembly).

[!tip] Best Practices

  - Используйте partial строго для разделения "код разработчика /
    сгенерированный код".
  - Применяйте частичные методы без модификаторов для хуков (hooks) жизненного
    цикла генераторов — это не дает накладных расходов на производительность
    (вызовы вырезаются, если не нужны).
  - Помечайте файлы с реализациями генераторов суффиксами .g.cs или
    .Generated.cs для игнорирования их статическими анализаторами (SonarQube,
    ESLint).
